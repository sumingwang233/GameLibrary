# ADR-0002 扫描覆盖与规则

- 状态：已接受
- 日期：2026-09-13（T20）

## 决策

1. 扫描输出必须携带结构化 **ScanCoverage**（枚举数/读取数/排除/失败/预算延后/未访问分支/续扫游标）；未知总量时 `estimatedCoverage=null`，禁止用已读/已读伪造 100%。
2. 扫描规则（ScanRule）按优先级执行：**SystemMandatory 排除不可被 Include 绕过 → 用户规则（priority 降序）→ SystemDefault → 默认继续扫描**；命中记录 winningRuleId。
3. matcher 只支持精确路径、分段子树、basename、扩展名、受限 glob（`*` 段内、`?` 单字符、`**` 跨段、`[]` 字面量）；不引入正则/表达式执行。
4. Watcher 事件队列上限 4096 个去重分支；溢出折叠为根 dirty 标记并触发完整核对。回调不做 I/O。

## 理由

“全盘扫描完成”若无覆盖明细，无法解释未识别目录，也无法验收 FS-10/FS-12。规则可解释性（为什么没入库）依赖 winningRuleId 与来源。事件风暴（存档写入）会压垮队列，折叠+周期核对是已知可靠模式。

## 被排除方案

- 按目录名全局排除 Data/Game/工具字样：上下文相关资源目录会被误杀（策划案 5.2-3）。
- 任意正则规则：注入与超时风险，v1 无需。
- 无限队列保留每个事件：内存不可控。

## 不可变约束

- 扫描对游戏盘只读；不写游戏文件。
- complete 表示“授权范围内所有分支已检查或按规则明确排除”，不等于全部识别成功。
- 暂停在安全检查点持久化游标；取消保留已完成合法更新，不触发 Missing 推断。

## 迁移影响

规则集版本（ruleSetVersion）进入覆盖报告；规则演进需对同一夹具重放比较。

## 验证用例

FS-10（Partial 与覆盖明细）、FS-07（排除有原因）、NW-03（溢出可补齐）、PERF-01/02/03。
