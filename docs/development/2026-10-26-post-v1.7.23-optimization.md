# v1.7.23 之后的代码与前端优化（第一轮）

2026-10-26。依据「k3.1 审查方案」的优先级，在合并 `origin/main`（v1.7.23）后的本地分支 `codex/optimize-v1.7.23` 上完成第一轮优化：连接与作业可靠性、分页与状态一致性、前端可访问性与动效。本轮未登记新版本号，未打包、未推送、未发布；工作区里用户对安装器与网站的改动保持原样。

## 范围与约束

- 不引入 Redux、路由、WebSocket，不重写 Host；沿用 `App.tsx` 作为组合根与既有 hooks。
- `games.list` 只做 additive 契约扩展，`limit` 缺省或 `<=0`（全量）行为不变，旧客户端无需修改。
- 不改数据库 schema，不新增第三方依赖；既有 operation、API 版本保持兼容。
- 只修改与方案相关的最小代码面；工作区里用户删除的安装器脚本、`website/next-env.d.ts` 等未跟踪/删除项不纳入提交。

## 问题与结果

| 方案项 | 原因与修复后的行为 | 主要文件 |
|---|---|---|
| P1 连接失效后永久握手失败 | Host 断开后 `HostConnection.InvokeOnceAsync` 会清空管道与握手，重建失败时异常向上抛出；`BridgeServer` 仍缓存这个连接对象，之后每个请求先读 `Handshake` 属性，直接抛「尚未完成握手」，而不是重连。现在 `EnsureConnectedAsync` 在空连接时先按缺口重建握手，重建失败才抛 `HostClientException(HostUnavailable)`；`BridgeServer` 在调用前确保连接可用，失败后丢弃缓存，停机时也清掉缓存连接。 | `HostConnection.cs`、`BridgeServer.cs` |
| P1 轮询无永久失败处理 | 扫描和标题翻译原来只在成功响应里更新状态：NotFound、管道断开等异常被吞成 `null` 或一条提示，循环继续每 500–700ms 空转，作业已经消失也停不下来。新增 `useJobPolling`，用连续失败预算终止轮询并给出可读原因；NotFound 立即结束；成功一次即清零失败计数。 | `useJobPolling.ts`、`useScanJobs.ts`、`useTitleTranslation.ts` |
| P1 分页游标错位 | 服务端按原始行做 `LIMIT/OFFSET`，前端却拿「合并去重后的本地数组长度」当下一页 offset；标题翻译等改动让某行更新后重新落位，重复行会让 offset 偏小，反复抓同一段甚至提前停止。`games.list` 增加 `nextOffset`/`hasMore`（`limit<=0` 时为 `null`/`false`），前端按游标推进，旧响应与本地回退路径保留。 | `GamesHandler.cs`、`useGamesQuery.ts`、`contracts/operations.v1.json` |
| 详情保存旧快照 | 选中项存整个 `GameItem`，后台 reload 或标题补丁之后详情继续显示打开瞬间的标题、收藏、封面。改为 `selectedGameId` 加列表外回退快照，渲染时优先取当前列表里的同 id 对象；相似建议跳转、`launch.exited` 等列表外路径仍可用。 | `App.tsx`、`selection.ts` |
| 审核部分失败清空选择 | `useCandidateReview` 把失败聚合成一个异常，`ReviewList` 等不到成功返回就清空全部勾选，失败项要重新找。现在批量结果按 `candidateId` 对齐，返回成功项与失败摘要；`ReviewList` 只清除成功项，整批异常时保留勾选，错误交给 `actionError` 呈现。 | `useCandidateReview.ts`、`ReviewList.tsx`、`App.tsx` |
| Unity 对话框提交串扰 | 单个 `submitting` ref 同时服务所有游戏，切换游戏后旧请求的失败会被标到新行。改为按 `gameId` 记录提交目标，状态合并只更新对应游戏，关闭对话框不丢其他游戏的进行中状态。 | `UnityTranslationDialog.tsx` |
| 幂等键复用 | 幂等键原来只按 `intent` 缓存，同一 intent 换参数会复用旧键，把新请求当成重放。现在键绑定参数指纹（稳定序列化），参数不同即生成新键；键仍由 `acquireKey/releaseKey` 管理生命周期。 | `api.ts` |
| 徽章对比度不足 | 11px 文本配 `bg-steam-soft` 在暗色约 3.32:1、浅色约 4.31:1。改用更深的文字色后，默认徽章暗色约 6.49:1、浅色约 11.74:1；steam 为 8.63:1/4.63:1；favorite、danger、success 的 `text-primary` 为 7.99–8.78:1（暗）与 12.83–13.33:1（浅）。 | `badge.tsx`、`index.css` |
| Sheet 标题关联失效 | Radix 的 `aria-labelledby` 指向自定义 `titleId`，但 `asChild` 的 `h2` 从未挂上这个 id。现在标题与描述都显式绑定同一组 id，屏幕阅读器能读出标题；同时补 160–200ms 进出场动画，`reduced-motion` 下关闭。 | `sheet.tsx`、`index.css` |
| 卡片嵌套交互元素 | `article role="button"` 里塞了 checkbox 和启动按钮，键盘与读屏语义冲突。改为普通容器加一张覆盖整卡的按钮，checkbox 与启动按钮作为兄弟节点叠在上层，整卡 hover 抬升保留。 | `GameCard.tsx` |
| 扫描 live region 过大 | `role="status"` 覆盖了每秒更新的耗时和取消按钮。现在只有状态标题进入 live region，计时器与按钮移出并标记 `aria-hidden`。 | `ScanProgressBar.tsx` |
| 骨架屏动效 | `animate-pulse` 常驻，改为 `motion-safe:animate-pulse`，由组件自己表达减少动态的意图。 | `skeleton.tsx` |

## 契约与兼容

- `games.list` 的响应新增 `nextOffset`（`number | null`）与 `hasMore`（`boolean`），是增量字段；旧客户端继续用 `total`/`items` 不受影响。`limit` 缺省或 `<=0` 时两个字段恒为 `null`/`false`。
- 审核部分失败是新返回结构，但对外 operation 与 MCP 工具签名未变；`ReviewList` 的 `onReview` 兼容返回 `void` 的旧实现。
- 幂等键仍在协议层使用同一个 `idempotencyKey` 字段，变化只在客户端缓存粒度，不需要服务端迁移。
- 未新增数据库迁移、依赖或配置项；`global.json`、`Directory.Build.props` 未改。

## 未执行与待办

- 未做人工验收：Host 被杀进程后的恢复、NotFound 提示、分页期间增删改、部分审核失败、真实键盘/屏幕阅读器/reduced-motion 检查都还依赖真实窗口与真机。自动测试只覆盖了 mock 传参和组件行为，不能替代这些验收。
- 方案第 5 阶段安全加固未动：CSP 需要先确认 asset 协议、字体与内嵌资源的实际加载方式；`withGlobalTauri` 与 `capabilities/default.json` 的收紧需要运行时确认；`GrantedPermissions=null` 的默认拒绝会影响第一方客户端；旧密钥清理要确认无引用文件后再删。这些改动都会改变启动行为，留到有运行环境时单独一轮处理。
- 批量 IPC（`GameBatchBar` 的 2N 次调用）、SQL 索引与 `assetCache` 实测仍未做；方案本身建议先完成分页游标，本轮已按此顺序。
- `host.stop` 的多客户端所有权仲裁仍按方案保留为条件项：当前桌面端是单客户端，改动会触及 Host 生命周期，不适合在没有并发客户端回归的情况下先动手。
