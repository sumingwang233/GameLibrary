# v1.7.14 安全与功能优化

2026-10-14。依据 [全仓审查](../code-review-graph/deep-review-2026-10-14.md)，在 v1.7.13 基础上修复 R1–R9，并先实施不需要新架构的 O1/O3/O5 小改动。版本登记为 1.7.14；本轮为本地开发交付，未打包、推送或发布。专项测试与必要编译已获授权，范围和结果见 [验证记录](v1.7.14-validation.md)。

## 安装升级的兼容边界

新安装器检查目标目录；新卸载器也只要求所属目录的进程退出。路径使用标准化绝对路径和目录边界进行不区分大小写比较，避免把 `install other` 识别为 `install`。

升级前仍会执行旧安装的卸载器。1.7.13 及更早版本可能按名称全局强杀进程，因此调用这些卸载器前要求所有已识别的 GameLibrary 实例关闭；版本未知时采用同样规则。1.7.14 及更新的卸载器使用目录范围检查。四语言提示说明旧版升级需要退出所有实例。辅助脚本只读查询，无法取得进程路径或查询失败也中止，不擅自结束进程。

无害同名进程桩验证了目标目录阻止安装、相邻目录不会被误认，以及旧版升级的额外限制。完整安装/升级/卸载流程尚未运行，不能把编译和进程判定回归当作安装验收。

## 低成本性能改动与暂缓内容

- O1：移除详情初始挂载的第二次 `profiles.list`，配置刷新保留请求顺序保护。收藏/标签/封面操作的整窗刷新合并、COUNT 共享仍待请求与耗时测量。
- O3：稳定游戏卡片选择回调；选中集合没有变化时返回原 Set，避免破坏卡片 memo 的收益。列表虚拟化和图片驻留策略暂不引入。
- O5：日志从最新文件向前读取，凑足行数即停止，按原时间方向返回；使用 `File.ReadLines`/`TakeLast` 限制内存。当前文件内部仍需向前扫描，写入仍扫描保留文件；有实际延迟证据后再优化。
- O2/O4/O6/O7：额外 bridge 通道、运行态淘汰、超大目录枚举预算、数据库索引/FTS 均保留为测量后的工作，不新增依赖、协议或 schema。

## 契约、恢复与回滚

保留既有 operation、API 版本和数据库 schema；诊断只增加待补写数量与审计失败数量。资产 ID 来自实际 Host 写入回执/事件字段，候选列表继续使用原 `candidates.list` 的 pendingReview/limit/offset 契约。SDK 10.0.401 与 `global.json` 不变，产品版本在 .NET、npm 和 Cargo 产品项同步。

取消客户端等待不代表 Host 已取消或回滚业务；连接失败后的结果仍需通过既有查询/收据确认。待补写原始结果驻留当前 Host，不承诺进程崩溃后恢复尚未落盘的内容。

本轮没有用户数据迁移。行为回滚可还原对应源码并重新构建；不要为了回滚改写库内标识符、删除审计历史或移动已有公开版本标签。生产发布需要独立授权及发布门禁。
