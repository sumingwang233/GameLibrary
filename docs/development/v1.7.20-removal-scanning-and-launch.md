# v1.7.20 文件回收、扫描与启动修复

基线为 `7e105e1`（v1.7.19），2026-10-17。本版为未发布源码，未打包或推送。

## 文件回收

旧版以 `GameCard.RootPath` 作为回收目标。手动添加 EXE 时，这个字段保存的是 EXE 文件，所以“删除游戏及原文件”只回收了该文件。

详情页现在按需调用 `games.get(includeRemovalPlan=true)`，显示实际回收路径和范围，再确认执行。手动 EXE 卡片会预览整个父目录，包括资源、存档和补丁；出现其他直属游戏入口、独立 SWF、活动游戏、游戏库根或链接时拒绝扩大范围。确认后重新检查，路径必须与计划一致。合集的 `fileGame` 和手动 SWF 保持单文件范围，文件被换成目录时拒绝回收。

```mermaid
flowchart LR
    Detail[详情：删除原文件] --> Preview[games.get：只读范围预览]
    Preview --> Confirm[确认 targetPath 与 revision]
    Confirm --> Guard[重新检查边界、共享记录和链接]
    Guard --> Intent[持久化 moving：目标与原 RootPath]
    Intent --> Recycle[Windows 回收站]
    Recycle --> Commit[记录 moved，再提交移除和忽略]
```

回收意图增加可选 `SourcePath`，区分卡片的 EXE 路径与实际回收目录；旧意图继续按原目标恢复，启动恢复不会重新回收文件。成功回执新增 `recycledPath`。沿用原事务、回收站和恢复机制，无新 DDL。历史数据仅做只读核查，个人路径和报告保留在本机。

## 扫描和审核

RPG Maker 的 JS/System.json、Kirikiri 的 XP3 能证明引擎结构，但不能证明目录是完整游戏。旧 collector 只检查置信度和 LikelyRoot，因而会把只有资源或补丁的子目录也创建为候选。

collector 现在要求检测结果包含实际存在的入口文件；引擎检测本身仍保留资源证据，供手动识别等调用使用。审核层通过 `ICatalogFiles.IsFile` 检查入口，阻止旧候选用空入口或目录路径入库。已有用户确认记录不自动移除；容器诊断和 Flash 的显式目录审核继续沿用原流程。没有新增按 `www` 或补丁目录名称一刀切的黑名单。

## MTool 接入

现有入口在“设置 → 游戏库”。游戏详情的“启动”页现在也提供“MTool 目录设置”，复用同一个设置组件。选择包含 `MTool.exe` 和 `loaders` 文件夹的目录即可；界面说明只需设置一次。

给非 Unity 游戏添加“未翻译”标签，或点击“生成或修复 MTool 启动脚本”，然后开始游戏。原有引擎模板和支持范围保持不变；不能自动配置时显示原因。设置目录不会提前运行工具或调用翻译 API。中文提示把面向用户的“配方”改为“启动脚本”，并同步四语言。

## BAT 与评分

启动方式文件选择器、创建、更新、计划校验和执行统一支持 EXE/SWF/BAT。BAT 使用系统目录中的 `cmd.exe /d /s /v:off /c`，脚本和参数分别加引号，不套用 EXE 的 ArgumentList 转义。路径中的展开符号及参数中的命令控制字符会被拒绝。参考 Microsoft 的 [CreateProcessW 文档](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw)和 [cmd 参数规则](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/cmd)。

用户选择已生成的 MTool BAT 时，翻译路由仍解析固定步骤，并向注入器传入原始游戏 EXE。它不会把 BAT 当成待注入程序，也不把任意自定义 BAT 视为已确认的翻译路由。

详情评分提示仅在没有星级时显示高亮和动效。已有评分的游戏再次游玩后正常打开详情，保留手动改分入口；异步刷新读到已有评分时也隐藏提示。

## 文件与兼容边界

| 文件 | 改动 |
|---|---|
| `GamesHandler.cs`、`DetailSheet.tsx`、`types.ts` | 回收预览、精确确认、目录范围与恢复意图 |
| `ScanCandidate.cs`、`CandidateReviewService.cs`、`CatalogFiles.cs` | 扫描入口筛选与旧候选审核检查 |
| `MToolTranslation.tsx` | 详情页目录设置与操作说明 |
| `LaunchingHandler.cs`、`LaunchRegistry.cs` | BAT 创建、更新、校验和执行 |
| `TranslationLaunchRoute.cs`、`MToolHandler.cs` | 选中 MTool BAT 时保留原始游戏入口 |

| 共享本地化与产品版本文件 | 四语言提示及 v1.7.20 版本同步 |

优先修复回收范围，再修复扫描和审核，最后补齐 MTool 操作入口与本轮新增交互。没有新依赖、数据库迁移或后台任务。旧客户端删除手动 EXE 时会因确认路径不匹配而被拒绝，需要升级客户端；回退后旧目录意图无法自动完成时会保留待核查回执，不重复删除文件。
