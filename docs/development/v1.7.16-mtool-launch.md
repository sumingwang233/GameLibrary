# v1.7.16 MTool 启动修复

2026-10-16，基于 `bea2941`。维护者反馈多款 MTool 游戏无法启动，授权隔离专项回归及必要编译。

只读检查本地已入库的 15 份生成脚本，确认旧解析器不接受 MTool 实际生成的 `@cd`、`@chcp`、`@echo` 静默前缀；另有 4 份使用固定绝对缓存工作目录，1 份使用 `BakinLauncher.exe`。旧回归使用手写的无前缀目录行，漏掉了这些生产输入。按实际结构补入回归，修复前两个前缀用例均失败，分别报告不认识 `@cd` 和 `@chcp`。

```mermaid
flowchart LR
  BAT[MTool 生成脚本：只读] --> Parse[BatRecipeParser：白名单提取步骤]
  Parse --> Discover[MToolAdapter：依赖存在性]
  Discover --> Route[TranslationLaunchRouteResolver：入口与工作目录校验]
  Route --> Run[LaunchRegistry：有界等待加载器，再启动工具]
```

文件级修改：

- `src/GameLibrary.Domain/Tools/BatRecipeParser.cs`：去掉单个静默前缀后继续既有白名单检查；支持固定绝对 `cd /d` 工作目录和 Bakin 单游戏参数形式。`%~dp0`、配方来源始终相对脚本目录；使用标准库保留盘符根目录。变量、控制流、复合命令及非工具启动仍拒绝，不执行 BAT。
- `src/GameLibrary.Host/Launching/TranslationLaunchRoute.cs`：支持 Bakin 加载步骤；保留 `MTool_Game.exe` 或 `MTool_Game_Tmp` 中的生成入口，避免替换回原始 EXE；生成入口必须存在且位于声明的工作目录，缺失明确报错。普通搬迁入口仍复用原重映射；继续校验工具、Hook、参数和工作目录。
- `src/GameLibrary.Host/Hosting/LaunchingHandler.cs`、`ui.json`：启动预览复用共同错误恢复建议；非 Unity 游戏提示检查外部工具/MTool 配方，不再一律推荐 BepInEx。新增建议同步四语言。
- 既有 `BatRecipeParserTests`、`MToolDiscoveryTests`、`TranslationConfigTests`：改用脱敏的实际生成结构，覆盖发现、计划、异步执行和不可回退边界；保留 `TranslationStepTimeoutTests` 回归。

Bakin 的本地静态成员检查发现其入口使用反射加载游戏启动器；检查未加载或执行目标程序集。配方继续遵循生成脚本的加载器→工具顺序及现有超时边界，真实 Bakin 翻译效果未验收。
