# 扫描边界与打开目录修复

## 审计结论

- `DirectoryWalker` 原默认深度为 12，超过上限的目录不会自动继续深入。
- 用户提供的合集实际只需扫描 3 个目录。只读查询现有数据库确认，两个子游戏均已入库，父目录也以 `container` 入库。因此该例的外层卡片不是深度不足造成的。
- `ScanCandidateCollector` 原来仍会检查游戏内部的引擎、资源及工具目录，并生成嵌套候选。
- Tauri 的 `opener:allow-open-path` 只开放命令，未配置路径 scope 时，插件会返回 `ForbiddenPath`。v1.4.1 的权限修复不完整。

## 调用关系与修改

```text
ScanJobRunner → DirectoryWalker → ScanCandidateCollector
                                  ├─ 未找到入口：继续深入
                                  └─ 找到游戏入口：停止该游戏的子树扫描
ScanCandidatePersistence → 只将游戏写入待添加列表，跳过合集诊断

DetailSheet → open_game_directory → 校验绝对路径且为已有目录 → 系统文件管理器
```

优先修复目录打开，再修复游戏发现边界。无路由、数据库 schema 或全局状态管理变更。

- 默认取消固定深度上限，保留分段预算、取消、排除规则与重解析点保护。
- 游戏主程序所在目录成为发现边界；资源和汉化工具不再被继续识别。合集的同级子游戏分别识别。
- 扫描根直接存放的独立 EXE/SWF 保持文件游戏语义，不阻止根下其他游戏目录被扫描。
- 已识别为可启动游戏的目录内，即使还有独立游戏，也不再自动深入；可将该子目录单独作为扫描根。
- 已有合集卡片和用户编辑不自动删除或迁移。新扫描不再新增合集候选。
- 目录打开改用只允许目录的原生命令，不开放任意文件执行权限；文件型游戏仍打开其父目录。
