# GameLibrary v1.7.5

## 简体中文

本版本根据 2026-10-06 架构审查改善恢复、启动、备份与文件回收的中断边界。

**正式发布，未验收。** 维护者于 2026-10-06 明确豁免本次发布前验收，要求发布正式版并注明未验收。本次仅完成生产与安装器编译；测试、独立检查和人工验收均未执行。这是本版本的明确例外，不表示检查已通过，也不改变后续版本的发布原则。

### 主要变化与修复

- 断线重连保留首次请求的库实例及数据纪元，恢复后的旧写请求不会自动绑定到新状态。
- 启动前登记尝试引用，统一幂等键作用域；宿主重启后无法证明的启动结果不会自动再次执行。纯数据库操作与完成回执共同提交。
- 备份的 SQLite 快照和封面复制共用写入边界，并核对快照引用的管理资产，避免只有清单哈希正确却缺封面的备份。
- 原文件回收记录阶段性意图；路径缺失且记录未变化时恢复入库移除，无法证明的情况要求人工处理，不重复回收原文件。
- CLI、MCP 的参数来自共同契约；修复封面 reset/crop 参数及修订校验、标签重命名误清颜色和 schema.get 入口漂移。
- 慢注入等待转为后台启动作业；桌面等待真实结果，支持已有取消、库租约和游戏级互斥。

### 升级与数据保留

先退出 GameLibrary 再安装，或替换便携版程序文件。保留游戏库数据、翻译凭据和原游戏。数据库仍为 schema 27，没有新增迁移或依赖；回退前先备份并处理未决启动/回收意图。`verification.report` 为写操作，调用方须携带幂等键；慢注入的 `launch.execute` 可能返回 accepted/jobId。详情见[架构实施记录](https://github.com/sumingwang233/GameLibrary/blob/main/docs/development/v1.7.5-architecture-plan.md)。

## English

This version addresses interruption boundaries in restore, launching, backup and recycling identified by the 2026-10-06 architecture review.

**Official release, acceptance not run.** On 2026-10-06 the maintainer explicitly waived pre-release acceptance for this version and authorized an official release with this disclosure. Only production and installer compilation completed; tests, separate checks and manual acceptance were not run. This version-specific exception does not imply passed validation or change future release policy.

### Highlights and fixes

- Reconnect preserves the original library instance and epoch; stale writes are not rebound after restore.
- Launch attempts are associated before process side effects, with matching actor-scoped idempotency. Unknown restart outcomes are never rerun automatically. Database-only mutations and their final receipts commit together.
- SQLite snapshots and managed cover copies share a write boundary; backup verification also checks database asset references.
- Recycling records durable stages. Database removal can recover when absence and unchanged identity/revision are proven; ambiguous cases require review without repeating file recycling.
- CLI/MCP parameters share the canonical contract. Cover reset/crop forwarding and revisions, omitted tag colors and schema discovery are aligned.
- Slow injection waits use background launch jobs, retaining cancellation, library leases and game exclusion. Desktop clients wait for the actual outcome.

### Upgrade and data preservation

Quit GameLibrary before upgrading. Keep library data, local translation credentials and original games. Schema remains 27 with no new migration or dependency. Back up and resolve pending launch/recycle intents before rollback. `verification.report` requires an idempotency key; slow injection through `launch.execute` can return accepted/jobId. See the [implementation record](https://github.com/sumingwang233/GameLibrary/blob/main/docs/development/v1.7.5-architecture-plan.md).
