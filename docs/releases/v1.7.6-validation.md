## 已有证据

- 只读数据库定位实际默认入口和 engine=`unity`，确认失败发生在游戏文件事务之前。
- 隔离复制实际 Mono 主程序集，旧脚本在 Write 阶段出现 `Mono.Cecil.AssemblyResolutionException`，缺失 `UnityEngine.SharedInternalsModule`。修复后助手 exit=0；离线端点类型解析 exit=0。真实游戏文件不变。
- IL2CPP 固定包来自官方 BepInEx BE-704 与 XUnity v5.6.2；SHA-256 在源码固定，32/64 位独立选择。组件只在使用时下载，不把私人配置打包。
- 四语言检查：672 个共享 UI 字符串、42 个安装器字符串通过。
- 前端针对性回归：UnityTranslationDialog、UnityTranslationSettingsForm、DetailSheet，3 文件 / 18 项通过。
- 后端最终专项分组通过：UnityTranslationTests 46 项（unity-v1.7.6-final.trx）、TranslationConfigTests 21 项（translation-config-v1.7.6-final.trx），共 67 项。IL2CPP 两种位数使用固定公开包在临时游戏中完成真实文件配置、启动路由检查、恢复和重试，未运行游戏或翻译 API。
- 首轮旧 MTool 测试仍期待同步 processCreated，实际 v1.7.5 契约已改为 accepted/jobId + prepared。更新为等待作业终态并继续断言 processCreated；相邻同步启动用例仍保持原断言，最终 21 项通过。
