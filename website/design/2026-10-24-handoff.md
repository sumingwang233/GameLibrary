## 页面与架构

页面顺序为：首屏 → 扫描、确认、启动三步 → 实机大图 → 本地管理优势 → 标签收藏 → Unity 翻译 → 启动方式 → 数据与文件 → 下载 → FAQ。

```mermaid
flowchart TD
  Routes["四语言 page / layout"] --> Page["MarketingPage · 服务端内容"]
  Routes --> Site["lib/site.ts · 语言、路径、版本、metadata"]
  Routes --> Bootstrap["themeBootstrap · 首次绘制主题"]
  Page --> Controls["GlassControls · Header / Screenshot / LocalTooltip"]
  Page --> Styles["globals.css · 视觉与响应式"]
  Page --> Assets["PNG 原图 / WebP 预览"]
  Controls --> Theme["lib/theme.ts · 主题偏好"]
  Bootstrap --> Theme
  PNG["PNG 源素材"] --> Sharp["optimize-images.mjs · Sharp"] --> Assets
  Config["next.config.mjs · 静态导出与生产前缀"] --> Routes
```

`MarketingPage` 集中组织四语言内容，`GlassControls` 承担客户端交互。语言是实际路由；主题、菜单和截图窗口使用局部状态。当前结构足以支持局部设计迭代，暂不需要新增路由库、状态库或组件框架。

主题逻辑由首次绘制脚本与选择器共用：新访客默认浅色，已有 Light / Dark / System 偏好继续生效。语言与主题菜单使用原生 `details`，手机导航与截图窗口使用原生 `dialog`；后续改外观时继续复用这些行为。

回滚以独立网站提交为单位，用 `git revert` 撤回页面、样式及对应说明；涉及素材或网站版本时一并撤回。推送、部署、打包和 Release 按各自的明确授权执行。
